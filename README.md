# ABO グループ成長シミュレーター v1.6（非公式）

**初めてのABOでも、3項目の入力からグループ人数・PV・成績別ボーナスの参考額を確認できる静的Webページ**です。

> 日本アムウェイの公式ツールではありません。公式の資格審査・過去の受給履歴は未確認です。6%リーダーシップは条件を仮定した概算のみ表示します。収入を保証するものではありません。一般公開や勧誘に使用する前には、BSM・QAS等の適用と承認要否について日本アムウェイにご確認ください。

## 実行方法

`index.html` をブラウザで開くだけで動作します（通信・サーバー不要）。GitHub Pages でもそのまま動作します。

## 入力

1. 全員の平均月間PV（万PV）
2. 1人が増やすフロント人数（本人も系列下位も共通）
3. 次の段が増える間隔（月。デフォルトは1か月）

任意：予測期間（初期値**12か月**、18/24/36か月も選択可能）、BSI・ブロンズ9・ブロンズ15・6%リーダーシップのチェック、詳細設定の「税込参考換算比率」（初期値 **1.59**）。ページを開くたび全入力を初期化し、追加ボーナスのチェック4種は**すべてON**で開始します。以前の保存データを読み込んだり、入力内容を端末に保存したりしません。

## 出力

- 月別の累計人数・月間PV・該当成績別ボーナス率
- 本人の成績別ボーナスの概算（グループ全体の率から直下系列の相当額を差引）
- 成績別ボーナス・BSI・ブロンズ9・ブロンズ15・6%リーダーシップの**各金額（選択・条件付き）**を合計と並べて表示
- ブロンズ9が0円の場合、月間達成率・個人1万PV・フロント3系列・12回上限などの簡潔な理由を表示
- フロントごとの率、およびセカンド・サード以降の各ABO1人あたり系列率の表示
- 条件付き6%リーダーシップ参考額（有資格SPのタイプと最低保証調整の簡易計算）
- 21%到達月、最初の4か月＋選択月の直近2か月の**月別・増加人数・累計人数**をコンパクトな表で表示、推移グラフ、月別CSV出力
- **表示は0か月目（現在）から開始**し、バーを右に動かす案内を表示。詳細を見たい月へ変更可能
- フロント別PV・達成率はスマートフォンでも折り返しにくい短縮数値＋3列のレイアウトで表示（数値の正確なPVはタイトル属性に保持）
- 月ごとの推移はスマートフォン時に「月・人数・PV・率・ボーナス」の5列に短縮、万・億単位で省略表示。横スクロールせず縦方向のみスクロールし、列見出しをスクロール領域内の上部に固定
- 月次ボーナスの補足は「BSI：○人達成」「ブロンズ9/15：○回目」などに短縮。細かい注意事項は折りたたみ表示
- 月ごとの推移一覧は人数上限100万人を超えた月を非表示
- 入力情報は端末に保存しません。起動時に旧バージョンの本ツール専用の保存キーを消し、画面を初期値に戻します（外部送信なし）。
- Cloudflare Pagesに `_headers` を追加し、`Cache-Control: no-store` でブラウザへのHTML保存を抑えます。ブラウザ全体のキャッシュを消去するものではありません。

## 計算の前提と制約

- 全員が同じ月間PV・同じフロント人数を継続し、設定した月数ごとに同じ構造で一斉に次の段が形成される理想化モデルです。現実の購入率・離脱率・発生月のばらつき等は含みません。
- 2026年9月版の概要書面にある**税込参考比率 PV:BV相当＝1:1.59**を利用した概算です（税抜の平均PV:BV比率は1:1.446）。追加の消費税は掛けません。商品ごとの実際のBV・税率を再現しません。
- 成績別ボーナス率は0%/3%/6%/9%/12%/15%/18%/21%を使用。
- BSIは開始時フロントが同じ月に登録し、当月から13か月間本人・各フロントが10,000PV以上と仮定した試算です。実際の登録日や対象個人の購入実績は未確認です。
- ブロンズ9・15は当月のPV・直下系列条件を確認しますが、昨会計年度の実績、過去の受給履歴、正式資格、会社審査などは未確認です。チェックは資格の証明ではありません。ブロンズ9は、直下3%以上の3系列、本人9%以上、本人パーソナル1万PV以上を仮判定し、シミュレーション上の受給回数1〜3回で5,000円、4〜6回で10,000円、7〜9回で15,000円、10〜12回で20,000円と試算します。
- 21%フロント系列が生まれた場合、チェックを入れると有資格SPタイプ（I/II/III）の実績上の条件と最低保証基準を考慮した6%リーダーシップの概算を加算します。ただし正式資格・会社審査・系列上位の特殊パスアップおよび多段21%系列は簡略化しています。実際の受給額ではありません。
- セカンド以降の購入PVはすでにフロント系列合計に含まれ、個別ボーナスを本人の金額に再加算しません（二重計上の防止）。
- 小売利益・活動経費・税金、その他のインセンティブは含めません。
- 人数は100万人を上限として計算を停止します。

## Cloudflare Pages 公開手順（推奨）

**公開前の確認：** アムウェイ概要書面のBSM・QAS等の規定に関する利用目的、承認要否を確認してください。Cloudflare Pagesの本番URLは一般にアクセスできます。

1. https://dash.cloudflare.com/ にログインし、**Workers & Pages → Create application → Pages → Connect to Git** を選択します。
2. GitHubを選び、リポジトリ **Koji-18/abo-growth-simulator** にCloudflare Pagesアプリがアクセスできるよう許可します。
3. 以下の設定で **Save and Deploy** します（Pagesの画面表示名は変更される場合があります）。

| 設定 | 値 |
| --- | --- |
| Project name | `abo-growth-simulator`（未使用の場合） |
| Production branch | `main` |
| Framework preset | `None`（フレームワークなし） |
| Build command | 空欄（または `exit 0`） |
| Build output directory | `.`（リポジトリ直下） |
| Root directory (advanced) | 変更しない |

公開URLは選択できたプロジェクト名に応じて `https://<project-name>.pages.dev/` となります。**GitHubのユーザー名はCloudflareのサイトURLに含まれません。**

Cloudflare PagesのGit連携では、`main` ブランチへの変更が自動的にデプロイされます。初回公開後はCloudflareの「Deployments」画面で「Success」を確認し、URLを開いて入力・計算・チェックボックス・CSV出力を検証してください。

公式資料: https://developers.cloudflare.com/pages/get-started/git-integration/ および https://developers.cloudflare.com/pages/framework-guides/deploy-anything/

## GitHub Pages 公開手順

**注意：一般公開前に、日本アムウェイへ利用目的・BSM等の規定に基づく承認要否を確認してください。**

承認等が確認できた場合は次の手順です。

1. GitHubで新しいリポジトリ `abo-growth-simulator` を作成する。
2. このフォルダの `index.html`、`README.md`、`.nojekyll` をリポジトリ直下へアップロードする。
3. リポジトリの `Settings` → `Pages` → `Build and deployment` で `Deploy from a branch` を選択し、`main` / `/(root)` を保存する。
4. URL `https://<GitHubユーザー名>.github.io/abo-growth-simulator/` で利用する（設定反映後）。

GitHub Pages公式ドキュメント: https://docs.github.com/ja/pages/getting-started-with-github-pages/creating-a-github-pages-site
